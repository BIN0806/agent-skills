# Task handoff

- Set the time window or comparison point: since the user's last substantive message, since an identified handoff, or a named revision. Reconcile available history with live state: diffs, commits, test outputs, PRs or artifacts. Treat prior reports as leads until confirmed.
- Lead with what the user can see now. Separate landed, in progress, failed, and unverified work. Give paths/links and exact checks where they help the next person reproduce the result.
- List decisions that actually need the user. Give choices, practical consequences and a recommendation when the evidence supports one. State the next action the agent can take independently.
- For long-running work, keep a small decision trail only where useful: decision, rationale, evidence and result. Keep it local unless publication is authorized. For a reset or handoff, record what can safely resume and what must be rechecked. Never invent activity, metrics or inaccessible history.
